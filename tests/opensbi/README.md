`fw_jump.bin` is OpenSBI's `fw_jump` firmware for the generic platform, built for the ISA Excalibur has, so that Grail can run it with `--bios` (spec section 7, "Firmware"). OpenSBI's own release binaries are built for `rv64imafdc`, and an Excalibur hart has neither C nor F/D.

- OpenSBI v1.9, riscv-software-src/opensbi @ cbf9f6734dd85a982c63e3cb5db7ffe09da839ca (`git clone --depth 1 --branch v1.9 https://github.com/riscv-software-src/opensbi`). BSD-2-Clause, see `COPYING.BSD`.
- Built with `scripts/build-opensbi.sh <opensbi> <out>`, clang, ld.lld, llvm-ar and llvm-objcopy 23.1.4 (the official Windows LLVM installer) and Python 3.13 (OpenSBI's Kconfiglib). The script does what `make LLVM=1 PLATFORM=generic PLATFORM_RISCV_XLEN=64 PLATFORM_RISCV_ISA=rv64ima_zicsr_zifencei PLATFORM_RISCV_ABI=lp64 REPRODUCIBLE=y platform-cflags-y="-Wno-error=unused-but-set-global -Wno-error=sometimes-uninitialized"` does, without GNU make; it explains each step and the two flags (warnings of clang 23 that v1.9's `-Werror` would make errors).
- 539856 bytes, SHA-256 `7346e7e936831322fa7a39e2c74939a20925044e69466ee31fe2703f7ac16043`. The build is reproducible: another checkout, anywhere, gives the same bytes.

The image is position independent and is loaded at 0x8000_0000 (`--bios FILE` loads a file that is no ELF there). As `fw_jump` on the generic platform (`platform/generic/objects.mk`), it starts the next stage at its own address plus `FW_JUMP_OFFSET`, 0x8020_0000, in S-mode with a0 = the hart id, and copies the device tree it was given in a1 to its own address plus `FW_JUMP_FDT_OFFSET`, 0x8220_0000, which it passes in a1: a machine needs more than 34 MiB of RAM for it (the tests give it 64 MiB).
