# Camelot: notes for Claude Code sessions

Camelot is a learning project: the Excalibur ISA (RV64IMA + Zicsr + Zifencei, M/S/U, Sv48 paging (Sv39 too), Xcal extensions; RV32 went in #159), the Grail emulator, the Merlin toolchain (merlin-as, merlin-ld, merlin-objdump, merlin C-subset compiler) and the Camelot OS. The spec is `docs/excalibur-spec.md`; the roadmap is its §11 and the tracking issue on GitHub (label `roadmap`).

## Picking up work

- Work comes from GitHub issues. Each one has a goal, spec references, acceptance criteria and dependencies. Check that its dependencies are merged before starting.
- Any open issue can be implemented. Code in the core pieces (encoder, linker relocations, compiler codegen) should stay readable and well commented, since it doubles as study material.
- If the spec is ambiguous or you change a design decision, update `docs/excalibur-spec.md` in the same PR.

## Hard rules

- **Rust, std only.** No crates in any `Cargo.toml`, including dev-dependencies. `Cargo.lock` must list only workspace crates. Windows APIs go through hand-written `extern "system"` FFI.
- **Windows-native.** Everything must build and run with `cargo` on Windows (and Linux). No WSL, no QEMU, no GCC cross toolchain. Build helpers are Rust (tests, `cargo xtask`-style binaries), not shell scripts. Existing `scripts/*.sh` are only for regenerating committed reference files with LLVM.
- **LLVM is a reference, not a dependency.** clang, ld.lld, llvm-mc and llvm-objdump (official Windows LLVM installer) may be used to produce golden files and to validate output, but `cargo test` must pass without them. Commit expected outputs.
- **No AI attribution anywhere**: no `Co-Authored-By` trailers, no "Generated with" lines, no session links, no Claude footers in commits, PRs, issues, comments or code.

## Layout

```
crates/excalibur        encodings, decoder, disassembler (shared by every tool), for RV64 and, for merlin-objdump, RV32: decode and Syntax take the width (Xlen); tests/disasm.rs checks both against llvm-objdump's text for tests/golden/rv{32,64}.s (scripts/gen-excalibur-golden.sh)
crates/elf              ELF reader, ELF32 and ELF64 alike (grail, merlin-objdump, merlin-ld), DWARF line tables (src/lines.rs: merlin-objdump -l, merlin-dbg) and compile units (src/units.rs: their address ranges and function names, which line table and name an address has for merlin-objdump -l, as LLVM's symbolizer finds them) and every debugging information entry as a tree (src/dies.rs: merlin-dbg's variables and types); tests/llvm.rs reads RV64 and RV32 files clang and ld.lld made as llvm-readelf and llvm-dwarfdump print them (scripts/gen-elf-golden.sh); and ar archives (src/archive.rs: read, as merlin-ld does, and written byte for byte as llvm-ar writes them, as `cargo xtask fs` writes libc.a; tests/archive.rs against llvm-ar's archives, scripts/gen-archive-golden.sh); and stripping a relocatable object of its debug information (src/strip.rs: byte for byte as llvm-strip -g, how /usr/lib's crt0.o and libc.a are installed; tests/strip.rs, scripts/gen-strip-golden.sh)
crates/grail            the emulator, an RV64 machine (src/cpu; a hart has Sv48 and Sv39, or Sv39 only with MachineConfig::paging / --paging sv39; an ELF32 program is refused; rom/diskboot.S: the boot ROM's disk loader, which boots a machine started with no program and no firmware from disk 0; `--bios none|default|FILE` / MachineConfig::bios: firmware, `default` the command's default and `None` MachineConfig's (src/firmware.rs, rom/firmware.elf built from firmware/) started by the ROM's hand-off as QEMU starts OpenSBI, with a device tree of the machine, src/devicetree.rs over src/fdt.rs)
crates/avalon-proto     Avalon protocol (framing, messages, Connection, Screen diffing, the Cursor kept apart from the frames), shared by the Avalon platform's programs; spec in docs/avalon-protocol.md
crates/gateway          user-mode NAT gateway (DHCP, DNS, TCP/UDP NAT, hostfwd) with its own frame send/recv API; grail wraps it as a NetBackend for `--net user` (spec 9.8). Must not depend on grail
crates/avalon           the Avalon hypervisor server: VM table, one thread per running VM (run_for slices, debug_continue's under a debugger), consoles, screen viewers and input, each VM's GDB stub for its one debugger (src/vm.rs, protocol section 6.8), RAM budget, virtual Ethernet switches (src/switch.rs)
crates/avalon-client    the client layer: VM control, debugging (DebugTunnel), virtual network and disk management operations, parsers/formatters for addresses, sizes, clocks, disk sources, network cards (shared by Round Table and Pendragon; reuses grail::parse_ram_size/parse_clock)
crates/round-table      the Round Table control CLI: argument parsing and text output over avalon-client (src/lib.rs `run`, main.rs is a thin wrapper)
crates/herald           Herald, the client that attaches to one VM: Session (the console streaming layer, terminal-free), screen::ScreenSession (the screen and input, window-free, drawing through a View) and the CLI, which puts the terminal in raw mode with grail::console::RawMode or shows the screen in grail::window (--screen); tcp::TcpSession and tcp::LineEditor are --tcp, a raw TCP connection with the line edited locally (a shell from kernel/user/shd.c)
crates/lake             the Lake storage server: a directory of disk images served over the protocol (one writer or many readers per image); Grail's client side is grail::lake::LakeDisk
crates/pendragon        the Pendragon web console: std-only HTTP/1.1 server, JSON API and an embedded page over avalon-client, and VM screens over a WebSocket (src/websocket.rs, src/screen.rs: Pendragon is the page's Avalon viewer, keys mapped with grail::keyboard::usage); API and security model in docs/pendragon.md
crates/camelot-fs       the Camelot filesystem on the host (docs/camelot-fs.md): format structs, ext4-style extent trees (src/extent.rs: reading, checking and growing them, as kernel/fs.c does), mkfs, fsck and log replay, a reader, the `camelot-fs` command; the kernel's side is kernel/log.c and kernel/fs.c
crates/merlin           the C-subset compiler, C to .s, for RV64 (LP64; `-march` takes rv64ima_zicsr_zifencei only) (src/codegen.rs explains the stack frames and code generation, src/abi.rs the calling convention, src/debug.rs what -g writes: .file/.loc, the files named as clang names them with their MD5s (src/md5.rs, RFC 1321), and a DWARF compile unit with the functions, their parameters, locals and blocks, the globals and the types; src/preprocess.rs also preprocesses .S assembly as `clang -E -x assembler-with-cpp` does, `merlin -E file.S`, checked against clang by the ignored tests/asm_cpp.rs; its diagnostics are clang 23's, text, position, notes and default warnings: tests/diagnostics.rs and its table in tests/diagnostics/, src/flow.rs the control-flow analysis clang's analysis-based warnings use, src/sequence.rs its -Wunsequenced)
crates/merlin-as        the assembler, RV64 (`-march=rv64ima_zicsr_zifencei`, the only one it takes), writing ELF64 (src/elf.rs); `li` is LLVM's RISCVMatInt (src/encode.rs, ENCODER.md); references in tests/golden (scripts/gen-encode-golden.sh, gen-li-golden.sh, gen-hello-ref.sh); src/dwarf.rs turns .file/.loc into .debug_line, byte for byte as LLVM does: tests/debug_line.rs, scripts/gen-debug-line-golden.sh; the $x<isa>/$d mapping symbols are clang's: tests/mapping.rs against clang's objects of tests/mapping (scripts/gen-mapping-golden.sh)
crates/merlin-ld        the linker, ELF64 executables of ELF64 objects (an ELF32 one, RV32 code, refused), which it reads through the elf crate (src/object.rs checks what it accepts); src/reloc.rs explains every relocation it applies; src/layout.rs `AT(lma)` load addresses and `ADDR(section)`; src/write.rs where the segments and headers go, as ld.lld places them; .debug_* sections are kept after everything loaded, and strip_debug/-S takes them out; archives (`lib.a`, `-L`/`-l` as ld has them) and `--start-lib` members linked in ld.lld's order (src/library.rs explains it); tests against ld.lld's links in tests/fixtures (tests/link.rs, fixtures/archive the archives' links; helpers in tests/common), and riscv-tests relinked (tests/riscv_tests.rs)
crates/merlin-objdump   the disassembler, RV64 (ELF64) and RV32 (ELF32), which it still reads; output matches llvm-objdump 23 (tests/golden, tests/golden/rv64; the RV32 riscv-tests it reads kept in tests/fixtures/rv32: scripts/gen-objdump-golden.sh)
crates/merlin-dbg       the debugger: a GDB remote protocol client (src/remote.rs: an RV64 machine, as the stub's target description says, riscv:rv64; over TCP, or a VM's stub tunnelled through Avalon, `--vm NAME`, avalon_client::DebugTunnel) with a command line (src/session.rs), backtraces by frame pointer (src/frames.rs explains the frame layout), source lines from line tables (src/source.rs: break FILE:LINE, step/next by line, list), variables and types from the debugging information entries (src/vars.rs: print, info locals/args, ptype, whatis, a backtrace's arguments, up/down; tests/vars/vars.c), Camelot's processes from the kernel's process table (src/camelot.rs: info processes, break LOC process PID or satp VALUE, add-symbol-file FILE program NAME; tests/processes.rs) and page tables walked over physical memory (src/paging.rs: process PID); `-- grail-args` runs a machine in process. Grail's side is grail::debug (the debug interface on Machine) and grail::gdb (the stub, `grail --gdb ADDR`; its Session is also what Avalon's VM threads serve, protocol section 6.8, tests/avalon.rs); docs/merlin-dbg.md
crates/xtask            build tasks (`cargo xtask up` builds the platform and runs Lake, Avalon and Pendragon as child processes until Ctrl-C, after seeding Lake's images directory with the bootable root image, `target/camelot-fs.img`, as `os-base` (`--demo` adds the VM `vm001` on its copy `vm001-disk0`, a Camelot VM's hardware: the firmware and 6 MiB), see src/up.rs; `cargo xtask examples` builds every example with merlin -E + merlin-as + merlin-ld, no LLVM, into `<name>.elf` (include/asm.h: REG_L/REG_S/SZREG/RISCV_PTR, the names Linux uses); `cargo xtask kernel` builds kernel/kernel.elf with merlin -g + merlin-as + merlin-ld, no LLVM (line tables in the committed kernels; the embedded and installed user programs stripped, and written with theirs to target/kernel/obj/user/<name>.elf; `-g` changes no loaded byte, tests/debug_info.rs), with the user programs of kernel/user built the same way and embedded through a userprogs.s generated at build time (in memory; a copy goes to target/kernel/obj, never committed), and kernel/kernel-disk.elf, the same kernel without the built-in programs, and `--cc clang` makes the clang -O2 + ld.lld reference build in target/kernel/clang; `cargo xtask fs` builds the root filesystem image target/camelot-fs.img from kernel/fs and the user programs, with /usr/include/user.h and /usr/lib/crt0.o, libc.a and user.ld, what the programs are linked from (src/fs.rs usr_files), bootable (bootloader and kernel-disk.elf installed), its size `xtask::fs::IMAGE_SIZE` (the one place to change it; the spec's "Root image" gives it in prose, and the boot test checks the two agree), no LLVM; `cargo xtask boot` rebuilds the committed crates/grail/rom/diskboot.elf, firmware.elf (from firmware/) and kernel/boot/boot.elf with merlin -E + merlin-as + merlin-ld; `cargo xtask hello` rebuilds merlin-as's ld.lld-linked hello reference (tests/golden/hello.elf); `cargo xtask ld-fixtures` regenerates merlin-ld's test fixtures with clang and ld.lld (src/ld_fixtures.rs: the flags, the sources copied from the examples), and `--out DIR` regenerates them into a scratch copy to diff with the committed ones)
kernel/user/as          the assembler that runs on Camelot (/bin/as), merlin-as rewritten in C (line tables included: dwarf.c), RV64 (`-march=` as merlin-as's), a program of several files; tables.h and tables.c are generated from merlin-as's and excalibur's tables by `cargo xtask kernel` (crates/xtask/src/c_tables.rs); crates/xtask/tests/selfhost.rs checks its objects equal merlin-as's
kernel/user/ld          the linker that runs on Camelot (/bin/ld), merlin-ld rewritten in C (no --Map), ELF64 executables (an ELF32 object refused), archives and -L/-l too (archive.c, library.c); tables.h and tables.c (relocation names) are generated from the elf crate's by `cargo xtask kernel` (crates/xtask/src/c_tables.rs); crates/xtask/tests/selfhost.rs checks it links every user program as merlin-ld does, and hello assembled and linked on Camelot; both tools compute with int64_t/uint64_t, merlin-as's and merlin-ld's i64/u64
kernel/user/cc          the C compiler that runs on Camelot (/bin/cc1: the directory is the program cc1, userprogs::RENAMED), merlin rewritten in C, landing in stages (#241), each file citing the merlin module it follows: so far the program's structure (main.c merlin's command line, util.c the arena of a translation unit, maps and UTF-8, diag.c merlin's diagnostics) and the preprocessor (lexer.c, preprocess.c: `cc1 -E` writes what `merlin -E` writes, C and .S, with its diagnostics); tables.h and tables.c (punctuators, directive names, predefined macros) are generated from merlin's by `cargo xtask kernel` (crates/xtask/src/c_tables.rs); crates/xtask/tests/selfhost.rs checks `cc1 -E` against merlin on every C and .S file of the repository but the firmware's, the diagnostics table's lexer and preprocessor rows and its PP_INPUTS, and its command line
kernel/user/ar          the archiver that runs on Camelot (/bin/ar), the elf crate's archive module in C: `ar rcs`, `t`, `x`, writing llvm-ar's archives byte for byte; crates/xtask/tests/selfhost.rs checks it against llvm-ar's (crates/elf/tests/archive) and libc.a, and C programs assembled and linked on Camelot from /usr as the host builds them
firmware/               Camelot's firmware (spec section 7, "Firmware"), RV64: sbi.S (the SBI runtime), entry.S (every hart's entry at 0x8000_0000, QEMU's fw_dynamic_info read, OpenSBI's fw_jump hand-off to 0x8020_0000), disk.S (the disk loader when no program was loaded), firmware.ld; built by `cargo xtask boot` into the committed crates/grail/rom/firmware.elf (`cargo test` checks)
kernel/                 the Camelot kernel (C + assembly, the .S files preprocessed with include/asm.h), in S-mode on the RISC-V SBI v2.0 (Camelot's SBI on Grail is firmware/sbi.S, in M-mode: BASE, TIME, IPI, HSM, SRST, DBCN; the kernel has no M-mode code and runs on the firmware, `--bios default`, loaded at 0x8020_0000; the kernel's calls are sbi.c, and nothing else in S-mode touches the CLINT or M-mode CSRs; tests/sbi.rs in crates/xtask drives every call); kernel.elf and kernel-disk.elf (without built-in programs, for bootable images) are committed (a higher-half kernel in Linux's layout on Sv48 or Sv39; its linker script, kernel.lds.S, preprocessed with merlin -E -P as Linux's vmlinux.lds.S; processes in the lower half with the LP64 system call ABI, #155, the shell pid 1; their memory mappings, mmap/munmap/mprotect, memfd_create's shared objects and /dev/fb0's memory, in mmap.c, shm.c and fb.c; poll() in poll.c, every kind of file's poll hook naming its wait channels in the caller's table (proc.c's poll_wait/poll_sleep: no lost wakeups); local sockets, AF_UNIX streams named by socket inodes, with sendmsg/recvmsg and SCM_RIGHTS, in net/unix.c and net/msg.c; devices through devsw, Linux's file_operations (file.h), with ioctl: /dev/fb0, Linux's fbdev, in fb.c, /dev/input/event0 and event1, Linux's evdev, in input.c, keyboard.c and pointer.c, and the framebuffer console, fbcon.c (its pixel loops in fbblit.S, its font kernel/font.c, generated by `cargo xtask kernel` from kernel/fonts/spleen-8x16.psfu: crates/xtask/src/font.rs), which kprintf and the console write to with the UART; the tests read its screen back from VRAM, tests/common's screen; tests in crates/xtask/tests/kernel.rs and processes.rs (polltest, unixtest), and threads.rs for munmap and polltest's lost-wakeup stress on several harts), rebuild them with `cargo xtask kernel` after changing the kernel, its user programs or merlin, merlin-as or merlin-ld (`cargo test` checks) (kernel/user: the user programs it embeds, C and assembly (a .S file preprocessed with include/asm.h, as lib/thread.S), built by xtask::userprogs, and kernel/user/lib their C library, linked like an archive; system calls in docs/camelot-syscalls.md; kernel/net: the network stack, a file per layer, specified in docs/camelot-net.md; kernel/fs: the root image's files; kernel/boot: the bootloader of a bootable disk, which camelot-fs mkfs --boot installs)
include/                asm.h, the names Linux's arch/riscv/include/asm/asm.h gives a register's worth and a pointer (REG_L, REG_S, SZREG, RISCV_PTR...), with RV64's definitions only (an #error for any other width), for every .S source: the examples, the boot ROM, merlin-ld's fixtures (`-I include`)
docs/                   ISA spec, Avalon protocol, Pendragon API, Camelot system calls, Camelot filesystem format (camelot-fs.md), Camelot network stack (camelot-net.md), merlin-dbg and Grail's GDB stub (merlin-dbg.md)
examples/               bare-metal M-mode programs (run with `grail --bios none`), each built from its .S source, preprocessed with include/asm.h; their .elf files are committed, rebuild them with `cargo xtask examples` after changes (`cargo test` checks)
tests/riscv-tests       prebuilt riscv-tests ELFs, the RV64 suites, and obj/ with their objects (merlin-ld relinks them)
tests/opensbi           OpenSBI v1.9's fw_jump.bin for the generic platform, built for Excalibur's ISA by scripts/build-opensbi.sh (clang, no make; its commit, licence and checksum in its README.md): a reference firmware, crates/xtask/tests/opensbi.rs (in the suite and in CI) boots the RV64 kernel on it (`--bios FILE`)
```

Reuse `excalibur` (register names, CSR names, decoder, `Inst::format`) and `elf` (reading ELF files, relocation names) instead of duplicating tables.

## Before pushing

CI runs on Linux only (Windows runners are expensive), so Windows is covered by running these checks locally on Windows before every push. Code behind `cfg(windows)`, such as the Win32 window, is only checked here:

```
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --release
```

`cargo test --release` is the whole suite: run it here before opening a pull request. GitHub's CI runs fmt, clippy and `cargo xtask ci` instead (`crates/xtask/src/ci.rs`): the important tests that take minutes, not the whole suite. Those are the unit tests, the toolchain against its references, the committed binaries current, the kernel booting and the documents. The kernel's filesystem integration tests and their crash tests, and the multi-hart, threads, self-hosting, networking and platform tests, run only here. A new test belongs in `ci.rs`'s list when it is important and quick. The ignored tests need what a plain run may not have, and have their own commands (README.md): a desktop (Grail's and Herald's windows), LLDB, clang and ld.lld (merlin's harness and ABI tests, the coreutils and kernel reference builds), or a quiet machine (Grail's throughput).

A **docs-only** change touches only Markdown (`docs/`, READMEs, this file), and no code, build files, committed binaries or files that go into an image (such as `kernel/fs/`). For one, run only the tests that read documents, not the three checks above:

```
cargo test --release -p xtask --test boot --test fs --test kernel --test up -- the_rom_the_bootloader_mkfs_and_the_documents_agree the_firmware_grail_the_kernel_and_the_documents_agree the_spec_gives_the_root_images_size the_format_document_matches the_system_call_document_matches the_readme_quick_start
cargo test --release -p avalon --test server -- the_readme_client_example
cargo test --release -p lake --test avalon -- the_readme_lake_example
```

A new test that reads a document joins this list, and `ci.rs`'s (`grep -rln '\.md' crates/*/tests` finds them).

Formatting uses `rustfmt.toml` (max width 110). Branch per issue, PR description says `Closes #N`.
